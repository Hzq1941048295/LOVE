# LOVE

FOR LOVE Agent

## 拾问 · 室内设计项目资料助手

面向室内设计新人、设计助理的 AI 产品经理转岗练习项目：从材料表、甲方纪要和图纸文字摘录中查资料、核对版本、整理变更待办。

**当前阶段：可交互产品原型。回答为人工预设，未接入真实大模型或动态 Agent 工具调用。** 项目、角色、价格、交期和资料均为虚构教学数据，不能用于真实施工、采购或合规判断。

## 快速体验

1. 在 GitHub 点击 **Code → Download ZIP**，下载并解压。
2. 用浏览器打开根目录的 **`demo.html`**，无需安装依赖或填写密钥。
3. 先体验 **Q04**（版本判断）、**Q16**（变更核查）和 **Q20**（经验沉淀）。

也可以直接打开 `dist/index.html`，或启动本地静态服务：

```bash
python3 -m http.server 8000 --directory dist
```

然后打开 <http://localhost:8000>。该服务仅用于本地预览。

## 已实现

- 12 份完整虚构资料，带文档 ID、段落 ID、版本与状态。
- 20 道测试问题，附标准答案、证据段落、验收标准和常见错误。
- 点击引用打开对应原文；按关键词查找案例、资料和个人记录。
- 变更核查与经验草稿：编辑、人工确认、本地保存和导出。
- 人工评测记录：先保存真实模型输出与备注，再标记通过或失败。
- 产品定位、需求取舍、访谈提纲、四周实践路线与模型接入说明。

个人记录保存在当前浏览器的 `localStorage` 中，不会同步到服务器，也不会修改原始项目资料。换浏览器或清理数据前请导出备份。个人确认不等于企业正式审批。

## 案例设计

虚构项目为 **澄园 · 128㎡样板间（CY-128）**，资料时点固定为 **2026-04-16**。

典型问题：

- 客餐厅现在用哪种砖？规格、颜色以哪份材料表为准？
- 较新的 R03 仍是未批准草稿，能否覆盖已发布的 R02？
- 甲方提出改木地板，需要核查哪些资料、找谁确认？
- 资料没有材料检测报告时，如何明确说明无法判断？

没有读取真实 CAD：图纸内容来自人为编写的文字摘录。

## 文件结构

```text
demo.html             # 无依赖单文件离线演示
dist/                 # 网页源码（HTML / CSS / JavaScript）
documents/            # 12份可导入知识库的TXT资料
corpus.json           # 结构化资料与元数据
test-cases.json       # 20题、标准答案、证据及验收标准
starter-prompt.txt    # 起步提示词和工具接口约定
check.mjs             # 数据、引用、计算、搜索和初始渲染检查
package.py            # 生成离线HTML与项目资料包
README.txt            # 面向初学者的详细起步说明
```

## 验证与打包

安装 Node.js 后，可运行无第三方依赖的检查：

```bash
node --check dist/app.js
node check.mjs
```

检查涵盖资料与问题数量、段落引用、面积和费用计算、日期计算、关键词匹配及初始页面渲染。`check.mjs` 还会重新导出资料、题目和提示词。

修改网页源码后生成离线版本和 ZIP：

```bash
node check.mjs
python3 package.py
```

`demo.html` 会更新，资料包写入 `outputs/`。预设标准答案通过这些检查，并不意味着真实 AI 回答准确。

## 下一阶段：接入真实 AI

建议先用 Dify 等可视化工具完成：

1. 导入资料，搭建“用户输入 → 知识检索 → 模型 → 带引用的回答”。
2. 保留文档元数据，核对版本和发布状态，正确处理未知与冲突。
3. 将检索、读取原文和计算封装为工具，允许有限次数补查。
4. 为草稿保存增加真正的后端、身份权限和用户确认校验。
5. 用真实模型输出重新跑评测，记录错误并迭代。

本仓库不含模型密钥、已部署的 AI 后端或可直接导入的 Dify 工作流。提示词里的工具名是接口设计，需实际实现并注册。

官方参考：[Dify Workflow Studio](https://www.dify.ai/workflows)、[知识检索文档](https://github.com/langgenius/dify-docs/blob/main/en/cloud/use-dify/nodes/knowledge-retrieval.mdx)。

## 如何作为求职作品

先找 3 位设计同行访谈，验证具体需求；再接入模型并记录真实输出。现有 20 题中，14 题用于调试、6 题建议预留，但由于标准答案已展示，正式评测还应新增未用于调试的问题。

可以如实展示产品原型、资料集、需求取舍与测试方法。用户访谈、模型效果、效率提升和企业部署经历，只有实际完成后才能写入作品集。
